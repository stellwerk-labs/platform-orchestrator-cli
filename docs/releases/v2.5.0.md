# octl 2.5.0

`octl deploy`, `octl score deploy` and `octl rollback` request server-managed
Runner log encryption by default. `octl logs <deployment-id>` and `--show-logs`
retrieve plaintext through the authenticated account without a client key.
IAM 2.8.0 must precede Control Plane 4.1.0 and Data Plane 4.4.0, which enforce
`deployment_logs_read`. Organization Admins retain access through `manage_all`;
Viewer, Deployer and ordinary metadata grants alone do not grant plaintext logs.
Grant the exact permission to roles and service users that need access.

`--skip-logs` disables capture. `--print-logs-key` explicitly selects caller-owned
encryption and prints the exposure warning. Historical caller-owned logs still
require `--key-file <file>` or `--key-file -`; lost legacy keys are not recovered.
`--encrypted` downloads ciphertext. Managed retrieval never falls back to
caller-owned encryption or key printing. Deployment output encryption is unchanged.

Runner logs are readable in terminals. `octl logs` and `octl rollout logs`
display Runner and Terraform/OpenTofu messages with compact metadata and
syntax highlighting for remaining JSON fields. Unknown fields and malformed
or partial records remain visible.

Pipes retain the original bytes by default. Use `--pretty` for readable
redirected output or `--raw` for the original content. Explicit rollout
`--out` output and encrypted ordinary log responses retain their existing
behavior. `NO_COLOR` and `TERM=dumb` disable generated colors while keeping
readable text. Human output escapes untrusted terminal controls; raw output
preserves those bytes intentionally.

Presentation flags apply after decryption. Requests retain certificate and
hostname verification with TLS 1.2 or newer; no TLS bypass is introduced.
The vendored public API contracts include managed logs and optional Module
catalogue summaries, preserving absent summary values as unknown.
