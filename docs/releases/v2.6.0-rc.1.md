# octl 2.6.0-rc.1

Project pipeline commands validate, import and export JSON/YAML documents, edit drafts with explicit revision checks, publish immutable versions with caller-owned request keys, and manage project policy. Forward and rollback defaults are independent. A conflict requires reading and reviewing the current revision; commands do not overwrite concurrent edits automatically.

Use `--pipeline-version` to select an exact published version for deploy, plan-only, Score deploy and rollback. Omitting the selector leaves directional default selection to the server. Ordinary deployments apply directly by default; requesting a Plan is explicit. The client resolves the publication and sends its immutable identity, while the server checks policy, target and Runner compatibility at admission.

Native Runner commands use the canonical registration and execution contracts. Deployment log commands can select retained Native phase captures, and deployment controls use the server's saved-Plan and supported recovery contracts. Applying a saved Plan does not authorize stale material or a second use; unknown infrastructure outcomes require reconciliation.

HTTP diagnostics omit submitted request and response values. Pipeline documents should contain references rather than secrets.

Use the matching server candidates. This release candidate uses explicit prerelease artifacts; stable package-manager channels and stable image aliases are unchanged by its candidate publication route.
