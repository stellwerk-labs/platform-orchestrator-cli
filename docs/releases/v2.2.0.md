# octl v2.2.0

## Draft authoring and testing

Module Drafts let you save and inspect several implementations under one
intended SemVer. Capture a saved revision explicitly for the intended scope,
then select that immutable snapshot with `deploy --draft-test`. Saving a Draft
does not capture or deploy a test. Later edits leave earlier snapshots, queued
work, and deployments unchanged.

Publishing creates an immutable Proposed Version from the selected revision and
closes the Draft. Making it Default remains a separate explicit action. Create
another Draft to continue editing after publication. Published Versions and Pins
remain unchanged.

Resource Types retain their identity and gain immutable interface versions. The
CLI exposes interface history and publication. New Module Versions can select an
interface explicitly; existing Versions keep their original binding.

## Compatibility

The CLI embeds generated API clients for the Control Plane and Data Plane. Use
matching server APIs and gateway routes. Existing HTTP operations remain
available. Older servers that lack a requested endpoint return a clear error.
An explicit Draft test never falls back to an ordinary deployment or a
published Default.
