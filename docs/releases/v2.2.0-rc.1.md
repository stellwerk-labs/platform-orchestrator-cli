# octl v2.2.0-rc.1

Prerelease for testing Module authoring with the coordinated CP 3.2, DP 4.1
and gateway changes.

## Edit, test and publish separately

Module Drafts let you save several implementations under one intended SemVer.
Read earlier revisions, capture a reviewed revision and run that immutable
snapshot with `deploy --draft-test`. Saving a Draft does not capture or deploy
a test. Later edits leave earlier snapshots, queued work and deployments intact.

Publication creates a separate immutable Proposed Version and closes the Draft.
Promotion remains a separate action. Create another Draft to continue editing
after publication. Published Versions and existing Pins remain unchanged.

Resource Types retain their identity and gain immutable interface versions.
The CLI exposes interface publication and history. New Module Versions can
select an interface explicitly; existing Versions keep their original binding.

## Compatibility

Use matching server APIs and gateway routes. Older servers that lack a requested
endpoint return a clear error. An explicit Draft test never falls back to an
ordinary deployment or a published Default.

Generated clients are pinned to public CP and DP sources and pass the normal
public-source checks. Final packaged upgrade and plugin compatibility checks
remain part of the coordinated release qualification.
